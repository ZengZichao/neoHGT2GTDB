| ① 簇字母后缀出现在非种级 | 文件名段 `f_Enterobacteriaceae_A`（Wigglesworthia 那个基因组）与 `g_Synechococcus_C`、`o_PCC-6307` | 已覆盖 |

| ③ 跨域 | 5 个细菌基因组 + 1 个古菌基因组 | 已覆盖 |

## 选项取值偏差（门禁规则 `choice_values_without_tests`）

第三十轮把"旗标被交给解析器"再往下推一层：**每个 `choices` 声明的取值都必须被某个用例交给
它所属的那个选项**。理由是 `--mimag any`——argparse 认它、选择器的档位表里没有它、也没有任何
用例写过它，于是它一直"合法但无效"，直到一次无关的改动把它变成报错才暴露。规则读的是三个
阶段 `arguments` 表里的真实 choices 列表（AST 解析，不依赖第三方包），匹配范围是**单个 test_
函数体内**同时出现该选项（旗标名或 dest）与该取值，因此 `for tier in ('high','medium',…)` 这种
表驱动写法算覆盖，而"文件里别处提到过这个词"不算。

第三十一轮把三个阶段一起转为门禁判定项，第三十四轮把第四张 CLI 表面
（`neoHGT gtdb` 自己的选项表）也并入判定：取值总数 104 → 107，未交给用例的取值必须逐条申明。
当前计数（取自动门禁报告，不在此手抄）：

- database 阶段：20 个带 choices 的选项、57 个取值、未覆盖 **0**。
- search 阶段：10 个选项、29 个取值、未覆盖 **2**（就是下面这一条）。
- analyze 阶段：7 个选项、18 个取值、未覆盖 **0**。

## 工作区外写入的可见性（`tools/run.sh`，第三十九轮）

`tools/run.sh` 是安全规则 14/15/16 的执法点：它拦下禁用的破坏性命令、拦下**命令行上写得出来的**
越界重定向，并在每次运行后列出 `$NEOHGT_ROOT` 内被改动的文件、把意图与产物写进
`neoHGT2GTDB-缓存测试/logs/commands.log`。第三十九轮补上它此前做不到的一半：
工具**自己不声不响**写进 `$HOME/.cache`、`/tmp` 之类的默认位置时，命令行上没有痕迹，
旧的运行器既不会拒绝也不会报告。现在它会扫描 `NEOHGT_WATCH`（默认
`$HOME/.cache:$HOME/.config:$HOME/.matplotlib:/tmp:/var/tmp:/dev/shm`），
把比本次运行起点更新的文件打印出来并记入日志的 `EXTERNAL` 行；
`NEOHGT_WATCH_STRICT=1` 时以退出码 4 失败。三个方向的自测是
`neoHGT2GTDB-临时文件/r39_runner_selftest.sh`（`verdict: PASS`），
其中"替身外部目录"放在工作区内——本轮没有真的向工作区外写过任何东西。
实测在本机跑 `pytest`（导入 pandas/matplotlib）两次，`EXTERNAL writes` 均为 0，
即 `tools/env.sh` 的缓存重定向从此是**被验证的**而不是被假设的。

第四十四轮补上这条链一直缺的最后一环：**有人读**。`tools/verify_workspace.py::check_external_writes`
在 IT-7 里读回 `commands.log` 的 `EXTERNAL` 行——指向工作区外的路径、日志缺失、

## 无人自动执行的核对工具（门禁规则 `tools/verify_plan_traceability.py::checker_tools`）

`tools/verify_*.py` 里有四个被文档当作"证据是怎么来的"引用，但**没有任何 CI 步骤、用例或别的工具**

第五十六轮把这条规则的采集面从 `verify_*.py` 扩到 `tools/*.sh`，因为本工作区的**纪律**

与彼此（run.sh 与两个见证工具 source env.sh）。这里要如实记下判据的弱点：
规则问的是"名字有没有出现在别的文件里"，而**提到不等于运行**——今天四者靠真实执行过关，
但一条注释或文档句也能伪造出"有运行者"。把它收紧成"出现执行标记（subprocess/`bash` 调用）"
与配套 env.sh 的"sourced 而非 executed"如何算，都在待办；env.sh 是被 source 的，

## 可达性偏差（门禁规则 `tools/verify_production_reachability.py`）

> 这台机器的输入 `docs/新增函数清单.json` 现在是**两半**：`functions`（本适配新增，211 个）与
> `upstream`（继承自上游，129 个）。只冻一半的话，清单冻结之后新写的函数谁都不认识，
> 门禁会一边少判一边继续报 "0 problems"。现在既不属于新增也不属于上游的名字直接报 `UNTRACKED`；
> 本地有干净上游时还可加 `--check-list`，把清单与重新计算的 diff 对成 missing / stale / upstream changed 三类漂移。

这台机器问的问题和覆盖率不同：**命令行能不能走到这个函数**。第三十轮那处
`--hybrid-lca-policy`（被校验、被印进报告、建库时从不调用）就是执行覆盖率看不见、
可达性一眼能看见的形状，所以工具只对**本适配新增**的函数提问（与原始上游树逐名比对），
并带一个反向对照：把 build 侧 `resolve=provider.resolve_shared_protein` 换成哑 lambda 后，
该函数必须重新变成"走不到"——成立，见 `缓存测试/reports/R32_production_reachability.json`。

当前申明为偏差的 4 个（都是**方案点名要的 API**，只是还没有 CLI 路径需要它们）：

> 这条列表原本是 5 个，其中 `resolve_taxon_ref()` 在第四十轮被移出：
> `neoHGT/analyze.py` 里 `from neoHGT.util import resolve_taxon_ref as _resolve_ref`
> 之后由 `read_input_gtdb()` 调用，而可达性图的行走当时**只沿"谁调用了谁"的名字走**，
> 既不把 `Analyze.slot = wrapper` 这类重绑定、也不把 `import … as 别名` 当作真正的入口边，
> 于是把一个确有调用点的函数误判为"走不到"。第四十轮修好遍历之后重跑，
> 它就不再出现在走不到的名单里。**这条申明是工具的缺陷，不是产品的缺陷** —— 记在这里，
> 因为"申报为偏差"同样是一种会被后人引用的断言。

- `rank_order()`、`rank_prefix()` —— 方案附录 B 的 util 表面，UT-1.6 逐条断言其语义
  （GTDB 7 级、`superkingdom` 别名到 `domain`）；生产路径用的是
  `rank_normalize`/`strip_rank_prefix`，所以这两个是"被承诺的查询接口"而非死代码。
- `gtdb_product()` —— 附录 B 承诺的"本地/官方产物名"判定；`meta.json` 现在直接落
  `product` 字段，未过这个函数。
- `rank_plural_label()` —— 方案第 842 行要求给 `rank_plural()` 补 `domain` 分支，而 RT-3 规定
  **既有函数签名与行为不变**，于是实现成新函数；`test_rank_plural_legacy_semantics_kept` 钉住
  旧函数原样，本函数等待一个需要复数显示名的调用点。

同一轮删掉的是真正没人承诺也没人用的 `gtdb.logical_rank`（`nodes.dmp` 秩的反向映射）：
写出方向由 `dmp_rank()` 负责，读入方向由 `rank_normalize` 的别名表负责，反向映射两头都不需要。
`search.is_gtdb_mode()` 则是**接线**而非删除：原先五处各自 `getattr(self, 'gtdb_root', None)`，
命名谓词反而没有调用者，现在五个判定点统一走它。
第五处是接线之后补测出来的——守护它的用例当时用**字面字符串**搜索
`"getattr(self, 'gtdb_root', None)"`，而那处正好被折行成两行，于是用例在还剩一个绕过点时就报了绿。
现在用例改在 AST 上匹配 `getattr(self, …'gtdb_root'…)` 调用并排除谓词自身，反向对照见
`缓存测试/reports/R32_mode_negative_control.json`：同一个折行写法，AST 规则抓到（行 2642），
字面规则抓不到。教训是**用文本匹配写的规则会被格式化绕过**，凡"扫源码找重复"的规则都该走语法树。

## 复用路径（`--from-scores`）上不生效的选项（门禁规则 `tools/verify_plan_traceability.py::reuse_inert_problems`）

`--from-scores` 从参数校验直接跳到预测：`read_input / assign_taxonomy / define_groups /
calc_scores / make_score_table` 五步全部不走。凡"读者只在这五步里"的选项，都会被解析、被校验、
可能还被打印——但**不可能改变本次结果**。第四十一轮量到 13 个，第四十二轮把 `--source` 从这一类里
救出去（见 `neoHGT/analyze.py::detect_gtdb_root`：现在两条路都只从这里问一次模式），
剩下 12 项写进 `neoHGT/analyze.py` 里的 `REUSE_INERT` 清单，运行时只点名用户**真的传了**的那些。

门禁不读这份申明就打勾，而是从 `neoHGT/analyze.py` 的调用图**重算**：从 `__call__` 出发，
拒绝进入上面那五步（连同 `Analyze.read_input = read_input_gtdb` 这类重绑定后的名字），
凡是可达读者为空的 dest 才算死。判定与例外：

| dest | 判定 | 依据 |
| --- | --- | --- |
| `close_size` / `input_cov` | 由档位写入，但本路径不生效 | 唯一读者 `neoHGT/analyze.py::define_groups`（跳过） |
| `self_rank` / `self_tax` / `input_tax` | 申明为不生效 | 分组与输入定性都发生在跳过的那五步；前两者与 `--donor-rank` 不同，报告阶段不消费自组秩 |
| `evalue` / `identity` / `coverage` / `maxhits` | 不生效 | 命中过滤在 `read_input()` 里做，复用路径不重读命中表 |
| `distal_top` | 不生效 | 只用于 `find_match()` 的 bit-score 截断，而 donor 已经在表里 |
| `weighted` | 不生效 | 打分发生在跳过的 `calc_scores()`；复用的分数已是算好的 |
| `taxon_synonyms` | 不生效 | 同义名解析在 `read_input_gtdb()` 里，本路径没有 `--close-tax` 之类要解析的引用 |

豁免两条，且豁免必须"仍在豁免"：`input_tax` 与 `self_rank` 在图上都有可达读者
（`neoHGT/analyze.py::domain_of_input` 读 `input_tax`，但只读字典形态，而字符串→字典的转换在
被跳过的 `read_input()`；`self_rank` 只被 `_rank_for_dump` 改写，消费者 `define_groups()` 不跑），
因此它们的"不生效"是**语义判断**而非图判断——必须有用例把理由钉住：
`neoHGT/tests/test_gtdb_pipeline.py::TestReuseRouteInertOptions::test_input_tax_is_read_but_only_as_a_dict`。
规则同时反向检查：豁免若已不再需要（那个 dest 本来就没人读）也判 problem——
本规则上线第一版就被自己抓出两处错判：把 `--input/--output/--taxdump/--from-scores` 当成
"路由自身的配件"豁免（实际它们在复用路径都有可达读者），以及看不见
`for k in ('taxdump', 'input', 'output'): getattr(self, k)` 这种间接读法（把有用的 `--input` 判成死的）。
第三个方向的检查由用例在**副本树**上做突变完成（不动发货代码）：删一条申明、加一条假申明、
留一条过期豁免，三个都必须报出来。

## 动态配置段的可达性（门禁规则 `tools/verify_plan_traceability.py::dynamic_section_problems`）

`get_config(self, key, f'{self.method}.{key}')` 把 config.yml 的**段名**交给了一个运行时取值。静态扫描能列出候选（选项的 `choices` 加上同一模块在此之前对属性写过的字面值），但**不能**断定哪个候选真的走到读取点——那是行为问题，不是文本问题。因此：候选段名在 config.yml 里不存在时，必须在这里写一行处置，而且门禁会去代码里核实那行处置（"拒绝"必须仍是一行点名了每个被拒选项的 `raise`；"归一"必须仍是一行 `if self.<属性> == <取值>`，其成立分支在所有路径上都把它改成别的取值，且读取点之前没人再赋回原值）。

| 段名 | 读取点 | 处置 | 代码证据 | 覆盖选项 | 理由 |
| --- | --- | --- | --- | --- | --- |
| `auto` | `neoHGT/search.py:306` | 归一 | `neoHGT/search.py:294` | — | `--method auto` 在到达 306 之前已被 294-302 解析成 `diamond`/`blast`/`remote`（三个分支各自赋值，没有留在 auto 的出口），所以 `auto.queries`、`auto.maxchars`、`auto.extrargs` 三条读取永不执行。config.yml 因此**不该**有 `auto:` 段——写了没人读 |
| `precomp` | `neoHGT/search.py:306` | 拒绝 | `neoHGT/search.py:2411` | `--queries`、`--maxchars`、`--extrargs` | 与上一行不同，`precomp` **能**抵达读取点：`-m precomp` 时 306 确实向 config.yml 要这三个键，而文件里没有 `precomp:` 段。缺的不是文档而是效果——预计算表整批读入（160-161 走 `[seqs]` 而非 `subset_seqs`），自比对又被 412-414 强制为内置法，唯一会用到这三个值的"批量 native 自比对"（930-948，其中 `self.method != 'precomp'` 在该路径恒真，是上游留下的死分支）走不到。于是 GTDB 路线明确拒绝（`guard_precomp_knobs`，定义 `neoHGT/search.py:2382-2417`，调用点 2517），且**不**补 `precomp:` 段：补了就等于再造三个"改了没反应"的旋钮，正是第四十轮 `database.gtdb.keep_placeholder_names` 的形状。普查见 `缓存测试/reports/R54_entry_expansion.json` |

## 第五十五轮新增交付物

* 新工具 `tools/round_witness.sh`：把**一整轮**的变更文件清单变成可查的东西。
  安全规则 16 要的是"本轮改了哪些文件"，而 `tools/run.sh` 只能回答"这条命令前后变了什么"——
  凡发生在两条命令之间的写入（编辑文档、手工 `cp`/`mv`）不在任何一条命令的窗口里。
  第五十四轮实测到这一点：那一轮的多数内容编辑在 `commands.log` 里没有行，
  变更清单只能事后手写。用法 `start <轮次>` / `stop <轮次>`；`stop` 写
  `缓存测试/logs/round<NN>_files.txt`，类别是 CREATED / MODIFIED / GONE / MOVED，
  其中 MOVED 只在**同名且 size+mtime 相同**时声明，改名一律如实留在 CREATED+GONE——
  这个见证要的是覆盖面，不是聪明的配对。两份快照都保留，工具自己的快照文件被排除在扫描之外。
* 拒绝的三种撒谎方式：没 `start` 就 `stop`（退出码 4，并且**不写**报告——空见证不得报"无变更"）；
  轮内重复 `start`（退出码 3，否则会抹掉重启之前的一切写入）；轮次号不是 1–3 位数字（退出码 2）。
* 自测 `临时文件/r140_round_witness_selftest.sh` 五例全过（`verdict: PASS`）：
  ① 命令窗口之外的写入必须被点名（同一例也证明窗口之内的写入同样被点名）；
  ② **前提本身**被检验——同一棵树里 `run.sh` 后续命令的变更清单确实不含那条 between-command 写入，
  而轮级见证里有；③④ 上述两种拒绝；⑤ 空轮必须写成
  "NOTHING CHANGED -- 若非属实，说明见证启动晚了"，而不是一张空表。
  头两遍跑这个自测时报红的都是我自己的测试缺陷（嵌套命令没建成目标文件；③ 的判定条件写反），
  不是被测工具——测试红了这句话本身不说明是谁错了。
* 发货用例 `TestRoundWitness` 6 例，其中一例要求"报告里的**变更行**不得出现工具自己的快照"。
  这条断言第一版写在全文上（`assertNotIn('.rw_92', text)`），被页眉里"快照出处"那行挡红了：
  那不是工具报错，是断言写宽了——出处可以提名快照，变更行不行。
* 本轮起点快照：67,853 个文件（`临时文件/.rw_55_before`）；`stop 55` 已执行，清单落在
  `缓存测试/logs/round55_files.txt`（5,636 行，`files before=67853 after=73414`）。
